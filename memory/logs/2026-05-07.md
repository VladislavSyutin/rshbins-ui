- Legacy-раздел вести в том же репозитории рядом с modern-слоем, не откатывая весь проект под стек ФОС и не разводя две долгоживущие ветки.

### Изменённые файлы

- legacy/components/loader-brand/styles.css
- legacy/components/loader-brand/LoaderBrand.jsx

### Решения

- Не добавлять --space-margins-outside-2xl в outside-шкалу: inside заканчивается на 2XL=32px, outside продолжает с 3XL=40px — единая непрерывная шкала. Вместо этого использовать --space-margins-inside-xl (24px).
- legacy-theme.css был промежуточным alias-слоем с неконсистентными именами (--legacy-color-border-default-focus → --color-border-default-default-focus). Простой стриппинг префикса —legacy- недостаточен — нужно сверять с реальными именами в tokens.css.
- design-tokens/ — source of truth, tokens.css — артефакт сборки. Никогда не редактировать tokens.css руками. Все новые токены добавлять через design-tokens/*.tokens.json и npm run tokens:build.
- Хардкодные значения в компонентах (padding: 11px, gap: 2px, width: 18px) — нормальная компонентная геометрия без токенов. Токены нужны только для значений из дизайн-системы (8px, 16px, 24px и тп) и на уровне шаблонов/страниц.

### Риски

- После удаления legacy-theme.css JS-файлы могут ссылаться на --legacy-* токены в inline стилях — CSS-скрипт их не найдёт. Всегда проверять JSX/TSX и stories при удалении CSS-переменных.
