### Итог

Зафиксирован новый устойчивый паттерн: chip-like segmented choice в этом UI kit строится из примитива Segment с optional иконками и композиционного SegmentedControl, при этом активный сегмент не должен реагировать на hover, а docs-превью состояний должны оставаться статичными и открываться в неактивном дефолтном состоянии.

### Решения

- Для chip-like segmented controls разделять primitive visual state и orchestration: Segment владеет геометрией, цветом, иконками и previewState, SegmentedControl владеет options и single-select логикой.
- Не переносить на такой control shared-border модель Gender: каждый сегмент должен оставаться самостоятельным chip с собственным фоном и focus-ring.
- В Storybook docs статичные preview-state примеры для Segment нужно делать невзаимодействующими и открывать docs в inactive default, чтобы реальный hover не искажал дизайн.

### Риски

- Если начать переиспользовать Segment как интерактивный docs-пример без статической изоляции, Storybook снова может показывать ложное hover-поведение.
- Inline SVG с currentColor удобен для таких иконок, но при более сложных multi-tone иконках может понадобиться отдельная icon abstraction.

### Follow-ups

- Использовать Segment как базовый primitive для следующих segmented и tab-like single-select controls, если у них нет общей рамки между item-ами.
- Если Figma добавит size- или state-варианты Segment, расширять их на уровне примитива и его stories, а не патчить каждую group-композицию отдельно.
