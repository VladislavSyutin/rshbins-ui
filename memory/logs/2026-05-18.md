### Запрос

Переоценить legacy-слой после обратной связи ФОС-разработчиков

### Итог

Проверены project memory, DOCX с описанием core-сервиса, zip с образцами UI-компонентов ФОС и текущий legacy-код. Вывод: предыдущий аудит совместимости был слишком оптимистичным, потому что фокусировался на React 17/Webpack 3 совместимости, но не на архитектуре переиспользуемости. Текущий legacy-слой ближе к Figma/Storybook-порту modern-компонентов, чем к универсальному UI kit ФОС.

### Изменённые файлы

- Файлы не указаны.

### Решения

- Для следующих legacy-компонентов целевой формат должен строиться вокруг универсальных компонентов и API, похожих на ФОС: dataId -> data-id, PropTypes, classNames, Readme с runnable-примером, Jest/Enzyme тесты для поведения.
- Нужно устранить React 18+/Vite-only конструкции в legacy: useId, import.meta.url/new URL, прямые SVG-url импорты и импорты SCSS из src/templates.
- Нужно снизить дублирование: выделять Field/Form/Panel/Input/ActionButton/LinkButton и input-валидационные helpers вместо множества узких компонентов с повторяющейся state/validation логикой.

### Риски

- ФОС-разработчики справедливо могут считать текущий legacy-слой непереиспользуемым: отсутствуют Form/Field/Fieldset/Panel/Select из присланных образцов, нет dataId/PropTypes/test-контракта, есть нативные button в сценарных местах и часть компонентов всё ещё не React 17-safe.

### Follow-ups

- Перед разработкой следующих компонентов подготовить legacy foundations: Button API adapter, LinkButton/IconButton, Form/Field/Fieldset/Panel, generic Input с mask/adapters, shared helpers для classNames/id/validation.

### Запрос

Разработать legacy Button и InputText в новой ветке для проверки в Storybook

### Итог

Создана ветка codex/legacy-button-input-foundations. Legacy Button переведён на FOS-подобный контракт с PropTypes, classnames, dataId -> data-id, buttonType/Button.buttonTypes и name как label. Legacy InputText получил PropTypes, classnames, dataId для native input, onValueChange(value), ref.focus(), error/customInputStyle aliases и clear action через универсальный Button. Обновлены Storybook stories, README и TS declaration files; добавлены зависимости prop-types и classnames. Проверки npm run typecheck и npm run build-storybook прошли, Storybook dev поднят на http://localhost:6006/.

### Решения

- Новые legacy foundations должны сохранять визуальную матрицу текущего UI kit, но наружу отдавать FOS-friendly runtime API: PropTypes, classnames, dataId, статические enum'ы и value-only callbacks там, где это нужно интеграторам.

### Риски

- Button всё ещё зависит от legacy Spin для loading-состояния; при копировании Button и InputText в ФОС нужно забрать также Spin или заменить loading slot на их loader.
