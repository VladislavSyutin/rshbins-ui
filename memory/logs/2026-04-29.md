### Запрос

Зафиксировать решение по организации legacy-раздела для передачи UI-компонентов разработчикам ФОС

### Итог

Проанализированы присланные разработчиками файлы: DOCX с описанием legacy-стека ФОС и ZIP с примерами старых UI-компонентов. Подтверждено, что ФОС использует React 17.0.2, MobX 4.15.7, собственный роутинг, Webpack 3.5.2, Babel 7 legacy, Jest 23/Enzyme, CSS/CSS Modules и старые UI-библиотеки вроде react-text-mask и react-select 1.1.0. Текущий UI kit остается современной Storybook-песочницей, но для разработчиков ФОС в этой же основной ветке нужно вести отдельный legacy-раздел с React 17-compatible версиями компонентов для копирования.

### Изменённые файлы

### Решения

- Не откатывать весь текущий проект/Storybook вниз до полного legacy-стека ФОС один-в-один.
- Не делать две равноправные GitHub-ветки для modern и legacy: выбран подход одной основной ветки с отдельной папкой/разделом legacy для React 17-compatible кода.
- Современный src/components и Storybook остаются мастерской для Figma-parity, токенов, визуальной проверки и удобной разработки.
- Legacy-раздел должен быть витриной для копирования разработчиками ФОС: React 17-compatible, без React 18/19-only API вроде useId, без зависимости от Vite/Storybook внутри компонентов, с готовым CSS, понятными README и списком файлов/зависимостей.
- Разработчики ФОС должны брать компоненты из legacy-раздела, а не напрямую из текущего modern src, иначе им придется чинить React 19/TS/Sass/Storybook-специфичные места.
- Если legacy-раздел сделан правильно, объем доработок на стороне ФОС примерно такой же малый, как при разработке в одной legacy-only ветке: в основном интеграция в их структуру, подключение CSS/токенов, валидации, сторов, роутинга и API.
- Ориентировочная структура: src/components для современной Storybook-версии, legacy/components для React 17-compatible копируемых версий, legacy/tokens для нужных CSS variables, legacy/README.md с правилами подключения.

### Риски

- Текущие компоненты используют React 18+ API, найденный пример — useId в InputText, Modal, Tabs, InputPassword, InputPhone и других компонентах; это не работает напрямую в React 17.
- Если legacy-раздел будет просто копией modern src без адаптации, разработчикам ФОС придется вручную заменять useId, переписывать TSX/SCSS/импорты, подбирать зависимости и исправлять события/маски.
- Если вести две независимые ветки, они могут разъехаться; поэтому выбран один репозиторный поток с legacy-разделом рядом с modern-кодом.

- На первом компоненте-пилоте проверить React 17-совместимость: убрать useId или заменить на совместимый helper, подготовить CSS и README, затем оценить реальную трудоемкость.
