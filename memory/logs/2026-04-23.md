### Итог

Добавлен template `AuthenticationPhoneConfirmation` с desktop/mobile и visible/hidden phone variants, Storybook playground/overview, обязательным `phoneNumber`, callback `onChangePhone`, resend-таймером и показом `NewCodeHasBeenSent`. Базовый `Toast` обновлён так, чтобы по умолчанию держаться 5 секунд, запускать closing-анимацию и затем переставать рендериться даже без обязательного `onClose`.

### Изменённые файлы

- `src/components/toast/Toast.tsx`
- `memory/knowledge/concepts/authentication-templates-layer.md`
- `memory/logs/2026-04-23.md`

### Решения

- `AuthenticationPhoneConfirmation` остаётся template-композицией, а не flow-controller: номер телефона приходит извне через обязательный `phoneNumber`.
- `+7 (952) 999-99-99` хранится только как Storybook/demo пример и не является runtime fallback внутри template.
- Кнопка `Изм.` реализуется через `onChangePhone`; в приложении flow-контейнер должен передать переход на предыдущий шаг.
- Resend-кнопка сама управляет минутным таймером: `59 сек` на старте, затем активная кнопка `Получить новый код`, toast `NewCodeHasBeenSent` после клика и повтор таймера.
- Toast-компонент должен уметь сам исчезать после `autoCloseDuration`, не требуя от родителя обязательного `onClose`.

### Риски

- `AuthenticationPhoneConfirmation` пока не связан с конкретным auth-flow контейнером; интеграционный слой должен явно передать `phoneNumber` и `onChangePhone`.
- `build-storybook` запускает `tokens:build`, поэтому generated token artifacts могут обновляться в процессе проверки.

### Follow-ups

- При появлении общего auth-flow контейнера подключить `AuthenticationPhoneConfirmation` к state предыдущего шага и передать реальный номер телефона.

- Часть компонентов с похожей логикой ФИО (`InputSurname`, `InputName`, `InputMiddleName`) пока дублирует sanitization/validation helpers; при расширении правил стоит вынести общий helper, чтобы избежать расхождения.
- Для `InputBirthDate` указан только required helper text; некорректные непустые даты переводят поле в error state, но без нового текстового сообщения, потому что продуктовый текст для этих кейсов не был задан.
