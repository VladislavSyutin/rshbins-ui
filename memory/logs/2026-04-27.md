## Session 2026-04-27

### Запрос

Миграция с Codex на Claude Code: проверка совместимости проекта, исправление шрифта Ubuntu в Storybook при запуске из git worktree.

### Итог

1. Подтверждена полная совместимость проекта с Claude Code — `AGENTS.md` читается автоматически, все соглашения соблюдаются.
2. Диагностирована и исправлена проблема с шрифтом Ubuntu в Storybook при запуске из git worktree:
   - **Причина 1**: `node_modules` в ворктри была пустой — создан симлинк на `node_modules` основного репо.
   - **Причина 2**: Vite блокировал шрифтовые файлы через `server.fs.allow` потому что симлинк разворачивается в реальный путь за пределами ворктри.
   - **Исправление**: добавлен `server.fs.allow` в `.storybook/main.ts` с путями к корню проекта и `node_modules` основного репо.
3. Изменения запушены в `main` на GitHub чтобы другие разработчики на Claude Code не сталкивались с той же проблемой.

### Изменённые файлы

- `.storybook/main.ts` — добавлен `server.fs.allow` для поддержки симлинка на `node_modules` в git worktree

### Решения

- При работе в git worktree нужно создавать симлинк: `ln -s <repo>/node_modules <worktree>/node_modules`
- Vite разворачивает симлинки при проверке `fs.allow` — нужно добавлять реальный путь, а не путь симлинка
- Запуск Storybook из основного репо (`npm run storybook`) не требует дополнительных настроек

### Риски

- При создании нового ворктри симлинк на `node_modules` нужно создавать заново вручную
- Путь `../../../../node_modules` в `main.ts` захардкожен относительно структуры worktree и может не работать в других конфигурациях

### Follow-ups

- Рассмотреть автоматизацию создания симлинка при создании нового ворктри (hook или скрипт)
- Проверить что `fs.allow` не создаёт проблем при запуске из основного репо
