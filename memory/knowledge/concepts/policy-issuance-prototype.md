## Что делаем

В worktree `codex/policy-issuance-prototype` проверяется идея первого шага оформления полиса в Storybook. Прототип расположен в `legacy/prototypes/policy-issuance/`.

## Границы

- Не изменять основной worktree `RSHBINS UI`.
- Не менять существующие компоненты в `legacy/components/`.
- Не пушить на GitHub.
- Сейчас нужен один desktop-размер L/Light без адаптива.
- Цель текущего слоя - быстро проверить сценарий; новые системные компоненты создавать только если идея будет подтверждена отдельным решением.

## Реализация

Прототип использует существующие legacy-компоненты `Header`, `Tabs`, `Button` и `Card`. Контент и изображения взяты из Figma selection-экранов:

## Сценарий оформления НС для семьи

В прототип добавлен переход с карточки `Страхование от несчастных случаев для всей семьи` на экран настройки полиса. Экран живёт в том же prototype-only слое и использует существующие legacy-компоненты там, где они уже есть: `SegmentedControl`, `InputPhone`, `Checkbox`, `InputCode`, `TextLink`, `Toast`, `Gender`, `InputSurname`, `InputName`, `InputMiddleName`, `InputBirthDate`.

Важные детали сценария:

- Есть режимы `Для себя` и `В подарок`; в подарочном режиме добавлены поля выгодоприобретателя, а gender не выбран по умолчанию.
- Кнопка продолжения на phone-step активируется только после валидного телефона, заполнения обязательных полей подарочного сценария и чекбокса согласия.
- После отправки телефона показывается loading 3 секунды, затем code-step; во время loading телефон остаётся редактируемым, disabled phone-field используется только на code-step.
- Code-step содержит таймер `Получить новый код через 59 сек`, resend-ссылку после таймера, success toast и возврат по `Изменить номер телефона`.
- Тарифы: индивидуальный/семейный; срок: 1/2 года; страховая сумма: 150 000, 250 000, 500 000, 1 000 000 рублей.
- `.Total` пересчитывает цену по таблице; для 2 лет показываются новая и старая цена, для 1 года только новая.
- Период страхования считается с завтрашнего дня на 1 или 2 года вперёд.

Визуальные решения текущего коммита:

- Divider оставлен только в режиме `Для себя`; отступ до и после линии выровнен по 16px.
- Цена в `.Total` использует `subheading-1-emphasized`; знак рубля наследует стиль цены без отдельного font-hack.
- Документ получил hover/pressed поведение как secondary button.
- Скролл перенесён под fixed header: прокручивается `main`, а не весь экран; нижний отступ формы сохранён через `align-items: flex-start`.
- Из ипотечной карточки убран дисклеймер про сервис `Лёгкая ипотека`.

## Сценарий ввода и проверки данных

После подтверждения телефона через code-step пользователь попадает в один из вариантов ввода данных:

- Любой телефон, кроме специальных тестовых, ведёт на экран ввода данных страхователя и паспорта.
- Телефон `79999999991` ведёт на экран ввода только паспортных данных.
- Телефон `79999999990` ведёт сразу на экран `Проверьте данные` с предзаполненными данными страхователя и паспорта.

Подтверждение номера на первом шаге должно сохраняться всегда: phone-step после loading 3 секунды переводит в code-step, а маршрутизация по тестовым телефонам выполняется только после отправки 4-значного кода.

Тестовые предзаполненные данные:

- Страхователь: `Сютин Владислав Игоревич`, дата рождения `02.06.2001`, пол `Мужчина`, email `syutinvi@rshbins.ru`.
- Паспорт: серия и номер `1234 567890`, код подразделения `000-000`, дата выдачи `20.07.1990`, кем выдан `ГУ МВД РОССИИ ПО Г МОСКВЕ`.

Экран `Проверьте данные` показывает блоки в порядке: персональные данные, паспортные данные, контактные данные, затем данные выгодоприобретателя для сценария `В подарок`. Блока `Coverage` в продукте нет. Выбор способа оплаты работает как radio group с вариантами `Яндекс Пэй` и `Банковская карта`.
