# DocumentsModal

Большая модалка для ознакомления с комплектом документов. Использует существующие Modal, Button, Checkbox, Spin и иконку chevron-down. Внешний вид оболочки и анимация берутся из Modal.

## Использование

```jsx
<DocumentsModal
  documents={documents}
  dataId="policy-documents"
  onClose={() => setOpen(false)}
  onConfirm={() => setAcknowledged(true)}
/>
```

Родитель монтирует компонент только на время открытия. Каждое монтирование начинает чтение заново. Подтверждённое ознакомление родитель хранит сам.

`documents`: массив `{ id, title, pages }` в порядке чтения. `pages`: `{ src, width, height, text? }`, где размеры и координаты текста заданы в единой системе исходной страницы, а `src` — изображение страницы. Элемент `text`: `{ text, x, y, width, height }`. Изображения сохраняют исходный вид PDF, прозрачный SVG-слой позволяет выделять текст. Идентификаторы документов должны быть уникальными, размеры — положительными. При смене комплекта перемонтируйте компонент с новым `key`.

`heading` по умолчанию «Ознакомьтесь с документами». `placement` по умолчанию `top-center`, для встроенного просмотра есть `inline`. `dataId` передаётся в `data-id`, дочерние элементы получают суффиксы `-checkbox`, `-close`, `-confirm`, `-scroll-to-end`, `-retry`. Компонент не импортирует данные продукта и не разбирает произвольные PDF в браузере.

## Поведение

- Ширина на компьютере 960 px, высота до 90% окна с отступами; на экране до 743 px — весь экран.
- Заголовок и нижняя область закреплены. Прокручиваются все страницы одной лентой.
- После 5% доступной прокрутки появляется кнопка перехода в конец. Переход мгновенный; после достижения конца кнопка скрывается до закрытия.
- Чекбокс виден сразу и недоступен до загрузки всех страниц и достижения конца. Возврат вверх не блокирует его.
- «Ознакомился (-ась)» доступна только после отметки. Вызывает `onConfirm` один раз и затем стандартное закрытие Modal с анимацией через `onClose`.
- «Закрыть» и нажатие на фон доступны независимо от загрузки. Крестика нет. Escape обрабатывается так же, как в обычной Modal: отдельного обработчика нет.
- Загрузка всех страниц закрывает область просмотра индикатором. При ошибке есть «Повторить загрузку»; повторная попытка сбрасывает прокрутку и отметку.
- При открытии фокус переходит в область документов. Tab остаётся внутри модалки, при закрытии фокус возвращается на исходный элемент. Прокрутка фона блокируется.

## Подготовка документов

В прототипе оформления локальные PDF и подготовленные страницы находятся в `legacy/prototypes/policy-issuance/assets/documents/`. Скрипт `scripts/prepare-policy-documents.py` генерирует изображения и текстовые координаты из оригиналов с помощью Poppler, pdfplumber и Pillow. Эти инструменты нужны только для подготовки файлов, в runtime зависимости не добавлены. Для ключевого информационного документа с текстом в контурах применяется локальное OCR через macOS Vision (`scripts/ocr-document-page.swift`); распознанный слой выделения может содержать ошибки, изображения страниц остаются из оригинала. После замены PDF нужно повторить подготовку и проверить текстовый слой.

Storybook: Playground, Mobile, LoadError. Визуальную проверку выполняет пользователь. Совместимость загрузки assets в FOS зависит от конфигурации принимающего проекта.

Проверки: `npm run check:documents-modal`, `npm run typecheck`, `npm run check:policy-components`, `npm run build-storybook`.
